## 固定設計

1. Snapshot envelope 帶 datasetId、sourceSeq、goLiveDate、server lease today／epoch、完整查詢範圍。每個 public 方法 server-only、有效 Google operator／holder；頁間與組合讀取前後比對同一 head identity／seq。傳入當前 expected lease epoch，切租約不得沿用舊結果。
2. 提供 `readSummary(range)`、`readReport(range, studentId|null)`、`readAccountHistory(studentId, range)`、`readAudit({dayId}|{studentId})` 這些能力；exported 具體 signature 可依附近 repository 慣例命名，但結果必須能供 P12c 完整重用，不要求 impl 為此另寫 plan。日期 today/week/month/custom 的範圍由純工具產生，依台北曆日、週一開始，range 最多31日；歷史帳戶前綴不受顯示range31日限制。
3. Summary 只加總最多31個日 heads，reuse 固定 day totals；已關帳日另讀最新 settlement 與補記求有效關帳現金，舊 entries 不計入。不存在的日期是無營業資料，不能捏造0元已關帳；缺該存在的投影則 fail closed。區間只加總流量與份數，不把每日openingCash/countedCash/effectiveCash存量相加當區間淨現金；day heads沒有orderUnpaid，未讀完整交易前不得用mealTotal-retainedReceipts或假0冒充它。
4. 歷史交易 query page size 預設100，以 businessDate ASC、createdAt ASC、documentId ASC；帳戶查詢另加 studentId 等值。每頁用 startAfter，走到 EOF，>200同日與>100帳戶必須完整。保留server Timestamp的seconds/nanoseconds排序鍵或已驗證query次序，不得轉成ISO毫秒後重排導致次序改變；ID比較須與Firestore字元序一致，不依執行機locale。範圍讀到交易後要與 day totals 對帳（account filter 時不可拿子集比全日，先用完整範圍再scope或分開核對）。不要 reuse 訂餐 loadSnapshot 的 today/backfill-only gate。
5. afterBalance：對欲顯示的每個帳戶讀期初起完整有效歷史，依固定排序（完整伺服器timestamp相同才用ID）累加；refund 扣 amount，voided不計，cashier餘額為不適用而非假0。讀完整帳戶末端後比對 student.currentBalance；前綴缺失、錯帳戶、schema錯誤、查詢失敗、不同sourceSeq或安全上限都不回可用報表。不從單頁或 currentBalance 反推。無cache最安全；如cache必須綁 dataset/revision/sourceSeq並失權失效。
6. 保留交易當時姓名／菜單／操作者快照；搜尋用當前 studentCode/displayName/aliases加交易時姓名定位ID，不覆寫原列。交易raw decoder reuse existing strict `decodeCloudOrderTransaction`；查詢範圍不能成為放寬schema的理由。
7. 回填標記同時包含 backfillDays 的日標記與 `isBackfilled(createdAt,businessDate)` 的交易標記；已關帳回填日也可查。補記以獨立 collection rows表示，含原 settlementRevision、direction、amount、reason、createdBy、createdAt及是否計入；不計入student餘額或餐點份數。
8. Audit 按 dayId/businessDate + seq 或 studentId + seq 做完整 cursor paging；decode immutable commands、保留 before/after、reason、actor/time，限制在同snapshot H。日結版本讀該日subcollection並驗連續版號、現day狀態與latest一致。不掃全 commands，不開全庫listener。
9. 同一 pure report model 提供摘要、原始／合併交易、日結／補記／稽核列與 sourceSeq；UI/CSV/print 後續只能消費它。合併以日別＋帳戶及既有語意分組，不跨日混成一列，保留原始IDs；voided原列保留稽核但不算有效合計。
10. CSV 保留既有transaction欄位順序，cloud metadata附在後面；獨立 builders 供 settlements、postCloseEntries、audit CSV（不將補記偽裝交易）。欄位包含必要的status/backfilled/sourceSeq/補記計入狀態與有效現金。對文字以含前導空白/tab/CRLF的formula prefix做防護；逗號、quote、換行正確quote。檢查既有 `serializeCsv` 的 callers，若強化共用函式，prototype regression必須通過。
11. 明列所有實際 composite indexes，包含 transaction account/date/time/name、commands day/seq與account/seq；適用大snapshot欄位免索引。Emulator 不驗正式索引可用性，僅記需使用者一起部署。禁止聲稱已部署。
12. 同步正式spec L07／§7.3：R6/R7較新，P12c的歷史更正正式入口只允許 open且lastSettlementRevision=0；驗未曾關帳歷史更正改變後日餘額而後日既有settlement不變。曾關帳學生歷史唯讀是本UI政策，backend原有reopened權限沒有在本批收緊，不能把UI限制寫成Rules保證。

## RED 與 GREEN

- 新 Emulator suite `cloudReadRepository.spec.ts`，專用 `EASYORDER_REQUIRE_CLOUD_REPORTS` flag，CI 增序列 proof step並檢查JSON totals>0／failed=0／skipped=0。
- 合成同日201+筆、帳戶101+筆跨頁與同時間ID排序；另測同一毫秒但不同nanoseconds且ID反序、混合大小寫合法UUID，防止JS時間截斷/locale排序繞過query契約；active/voided/refund/cashier、跨台北週一／月底、改名alias、已關帳回填日、新舊補記、日結版次。
- 頁間插入command使head變動要STALE；查詢/前綴不完整、head餘額不符、失權、maintenance、schema壞資料不回部分snapshot/假餘額。測試規模可用Admin合成seed，但驗證讀取必須經holder client與真Rules。
- 純projection數字與dayheads對齊；scope單一帳戶與all、原始/合併、CSV injection矩陣（前導tab/CRLF/空白、=+-@、quote/comma/newline）及份數/金額一致。
- 本批沒有UI，不以此宣稱R01/L07端到端完成；只完成資料層，P12c需真UI E2E。
- lint/build/全Vitest、targeted Emulator序列、受影響backup與E2E；app tsc對pinned base無新增診斷；精確記命令/exit/counts/skip/未跑原因，不用一般Vitest skip當Rules pass。
