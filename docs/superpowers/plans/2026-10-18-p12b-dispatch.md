## 已定稿資料契約

介面接合待 P12a exact-head review 後再次核對：P12a `CloudLedgerDateRange` 使用 `{kind,startDate,endDate}`，本批 command payload 使用 `{start,end}`，adapter 必須明確轉換，不能以型別斷言掩蓋不同鍵名。發起 command 的來源 H 必須來自已完成報表 envelope，不從各列 command.seq 推測；UI 的 summary-only 結果不能作為明細已完整的證據。

- Export：`{exportType, dateRange:{start,end}, scope:{studentId:UUID|null}, sourceSeq}`。exportType 為 `transactions-original | transactions-merged | settlements | post-close-entries | audit`。
- Print：`{printType, businessDate, dateRange:{start,end}, scope:{studentId:UUID|null}, sourceSeq}`。printType 為 `ledger-original | ledger-merged`，businessDate 是位於 dateRange 內的 anchor；真實起訖日也必須保存在 print model，週月列印不得只記一個日期。
- 範圍為有效 Gregorian 日期、start<=end、最多31天。scope=null 表整段區間；單帳戶scope只能是合法 UUID，不能用姓名／編號替代或保存自由搜尋文字。post-close-entries／settlements 的scope必為null；account audit/transactions可指定帳戶。
- range 驗證是曆日合法性，沿用 `validCalendarDate` 而非會拒絕未來日的 `validTaipeiDate`；本週／本月可包含尚未營業的未來尾段，亦可含上線日前的合法空白日期，這不授權未來業務寫入。inclusive 最多31日等價於 end-start<=30日，31日成功／32日拒絕須跨月測。Print anchor 同樣只須合法且在 range 內，不要求它是已有交易的日子。
- `targets`／`expectedRevisions` 空 map；command.studentId 與 payload.scope.studentId 相等。RecordExport.businessDate=null；RecordPrint.businessDate等於payload.businessDate。reason=null、zero cashEffect、actor/committedAt由Auth/server注入，before/after只有head。
- sourceSeq 是產出固定報表快照的 H，非負安全整數，H<=提交前head.seq；不強迫H等於提交前seq，允許輸出已標示來源序號的固定快照。不能在未知結果重試時換H、範圍或模式。
- head只有seq+1／lastCommandId／updatedAt改變，其餘head metadata不變。規則必須驗command與實際before/getAfter head的綁定；只寫command或只寫head都拒絕，fake projection／actor／cash／reason／多欄／少欄都拒絕。

## 實作與 RED/GREEN

1. 先建立 schema／repository／raw SDK RED；補兩kind進enabled union與各enum consumer，保留未知kind拒絕，舊兩種「disabled kind」測試不得變成空test.each或skip。
2. Rules 巢狀放在 `validCommandCreate` 最後一個operand；不加頂層OR，不改共用昂貴helper。依RecordBackup的head-only模式，不複製無關業務驗證。

   Rules 接線固定：保留共用 `headCommand`／`validHeadAdvance` 原樣，避免讓舊 CreateStudent +3 再付全域判斷成本。新增 report-action helper 只由 command-create terminal branch 呼叫，直接取得實際 `get(dataHead)` 與 `getAfter(dataHead)`，完整綁定 `command.before == {head: actualBefore}`、`command.after == {head: actualAfter}`，而非只對 command 自帶 before/after 做互相比對。既有 head rule 的新 command existence／不可孤立推進與 validHeadAdvance 繼續生效。不能照抄 RecordBackup 只核對 committedHead 的 seq/id/time 後就省略完整 after map 綁定；也不必為新 kind 往每個舊 head 評估路徑加 && guards。raw SDK 要驗 fake before/after metadata 與多餘 projection；配對寫入證據與預算端點都要保留。

   command 側 helper 同時必驗 `actualAfter.seq == actualBefore.seq + 1 == command.seq`、`actualAfter.lastCommandId == commandId`、`actualAfter.updatedAt == request.time`，不能只比 actual maps；command-only 寫入時 head rule 不執行，這些條件才會拒絕 getAfter(head)==get(head) 的孤立命令。兩命令共用一個 head 推進亦須拒絕。此為獨立 plan review GO 所列實作 acceptance。
3. adapter 定案為 `createCloudReportActionRepository(db, options)`，回傳 `recordExport(input)`、`recordPrint(input)`、`readCommand(commandId)`，沿用 `createCloudDayCloseRepository` 的 typed wrapper 形狀與 `CommandResult`／`CommandReceipt|null`，委派既有 command repository。Export input 為 commandId、leaseEpoch、exportType、range（P12a CloudLedgerDateRange）、scope、sourceSeq；Print 將 exportType 換 printType 並加 businessDate anchor。wrapper 明確轉換 payload range，canonical targets／expectedRevisions 皆空；writer 導出頂層查詢欄。同ID同輸入回原receipt，同ID不同scope/range/sourceSeq拒絕，unknown不能當明確失敗。ID 與固定輸出模型由 P12c 呼叫端先建立，不新增會自行換ID的 prepare/retry factory。
4. backup decoder與replay完整接受這兩kind，驗payload與head-only before/after、seq進展、actor/time、zero cash、scope對頂層查詢欄；重播不改business projection。舊備份仍可讀；manifest篡改及replay層分別有拒絕證據。
5. 真命令round-trip：業務資料→RecordExport(all/original)→RecordPrint(week/merged/account)→匯出加密備份→解密→replay，驗head增加但學生、交易、days、settlements、postCloseEntries不變。
