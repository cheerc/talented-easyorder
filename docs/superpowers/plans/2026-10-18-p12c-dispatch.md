## 區間稽核的接合定案

本段是 coordinator 因 plan review 發現原 day/account API 不等於 range API 而補齊的讀取政策；在 P12c 實作，不增加 write kind，也不要求 P12b 改批准 payload。

- 允許最小擴充 `cloudReadRepository.ts`／`cloudLedgerReport.ts`／`cloudLedgerExport.ts`、其對應 tests 與 `firestore.indexes.json`；既有 P12a CI proof 必須實際執行新增 reader cases。新增 `readAuditRange(input: CloudReportInput)` 與帶完整 range/scope envelope 的結果，保留既有 day/account API。
- 日期歸屬：command.businessDate 非 null 時按該營業日歸屬；為 null 時按 server committedAt 的台北曆日歸屬。畫面說明「沒有營業日的操作依記錄日期列入」。這包含已入帳的匯出／備份／學生基本資料等操作，不可默默漏掉 null-date commands，也不可把整個帳戶歷史冒充所選 range。
- all-scope：聚合 range 各日的完整 day audit，再以 `businessDate == null`、committedAt 的台北起日含至迄日次日不含，做 server query 與完整 cursor paging；按 committedAt、documentId 排序讀 EOF，decode 後驗 seq<=H，再與日資料合併按 command seq 排序。不是掃全庫 commands；新增所需 `(businessDate,committedAt,__name__)` composite index。日期 query 不因篩選 seq 而隱藏壞 seq；所有 raw/decoded 日期、時間、ID、scope 均驗證。
- account-scope：沿用完整 account audit（studentId 等值、seq<=H），再用上述日期歸屬篩選；null-date 命令只要其頂層 studentId 符合就可納入，不包含其他帳戶或 global-null studentId 的命令。
- 所有日子／null-date pages 必須和同一外層 context 的 datasetId/H/epoch 相符，且最後再驗 context；任一失敗整份失效。跨集合結果的 commandId/seq 不得重複或衝突，不能默默去重掩蓋不一致。禁止全 commands listener／全歷史全庫掃描。
- derived audit model 明列有效歸屬日期及依據（營業日／記錄日），UI／CSV 消費同一欄位。Audit CSV 在既有欄位後附這些 metadata，保留原 command.businessDate（null 仍空欄）及 command seq／snapshot source_seq 的區別。
- audit 是報表來源 H 的固定 prefix：本次 RecordExport/Print 的新命令在 H 之後，不必出現在自己發起前的輸出；重載後符合日期/scope時才列入。不同 H 的 audit/report 不可拼接輸出。
- RED/GREEN：跨3營業日與合法空白日；null-date commands 在台北午夜前後（同UTC日期不同台北日期）的含／不含界線；all/account scopes、不同學生/global操作；先前 RecordExport null-date 可列、本次 H+1 不混入；多頁 null-date query、缺seq/壞schema、H/epoch中途變更、重複seq與失權均 fail closed。沿既有 orphan/sort-field 防線，不把 Admin seed 當合法寫入證據。

1. 只對完整固定model啟用動作；scope與模式與畫面明細一致，記sourceSeq。輸出transactions原始/合併、settlements、post-close-entries、audit；無帳戶意義的日結/補記輸出只能all scope，UI有明確範圍說明。
2. 點擊時固定內容、range、scope、mode及commandId→提交P12b稽核→確認receipt→發起download/print；pending/unknown不再產生新ID或重複觸發瀏覽器動作。成功訊息只說「已發起」，不說「已保存／已印出」。
3. Print model包含真實起訖日、scope、模式、sourceSeq及完整rows，不只目前可見頁。使用同頁print surface與print CSS，避免await稽核後才window.open造成popup被阻擋；print surface固定於這次action model，不能被之後非同步query覆蓋。
4. React effects／StrictMode重跑不得對同一已確認command重複發起動作。瀏覽器取消列印仍保留「發起」稽核，不能宣稱知道使用者印了幾張；分頁關閉/重開的持久故障處理屬P13，本批不新增本機帳務儲存。
5. 畫面／CSV／print均使用同projection，不能各寫一套金額/份數/合併/標記算式；保留CSV既有欄位與安全escaping，合法負數餘額不可誤成公式。

## Coordinator 執行中定界：null-date 查詢（2026-10-19）

靜態檢查發現 `readAuditRange` 額外的 null-date document-ID proof 沒有 committedAt 日期界線，會讀整個 null-date partition；這違反上文有界查詢政策，必須移除。all-scope null-date 只執行已定案的 committedAt 起迄界線／排序／documentId tie-break cursor 到 EOF，再逐份 decode、驗 seq<=H／日期／scope 與最後 context。不同日 query 的 seq/documentId completeness proof 保留，各自仍限一個營業日；account 分支的完整帳戶歷史也保留。

沒有 committedAt 的 null-date 文件無法依已定案日期索引歸屬，不為偵測它新增全 partition 掃描。明確揭露範圍：fail-closed 保證適用查詢實際返回的 raw rows、整體 context 與相符範圍；不能宣稱全庫壞文件偵測。不要改 Rules、舊 readAudit 或舊 P12a 契約來掩蓋這個邊界。

回歸：在所選日期外放大量合法 null-date commands，短日期查詢仍只讀所選時間範圍，不因無關歷史超出 MAX_AUDIT_COMMANDS 而失敗；透過 query instrumentation／adapter trace 明確證明沒有缺日期界線的 null-date query。所選範圍內 missing/invalid seq、壞 schema、重複 seq、H/epoch/holder變更仍整份失效。原來依靠全 partition 才會發現的 missing committedAt 測試，改為明確的索引可見性限制與範圍控制，不保留錯誤的能力宣稱。
