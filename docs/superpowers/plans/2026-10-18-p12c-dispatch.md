# P12c dispatch brief：正式報表與查帳介面

Owner：coordinator。狀態：草稿未派工；pinned base、實際 P12a／P12b exported interfaces 待前批收據合併後由 coordinator 補齊。

依據：[執行計畫](2026-10-18-p11c4-p12-coordination-plan.md)、正式 spec R01／L07。Impl 不寫 plan、不自行改下列產品／資料政策。

## UI 與資料責任

- 新增 cloud `CloudReportPage`（F2）與 `CloudAccountHistoryPage`（F5）及 tests/CSS、必要 controller hook；在 `App.tsx` cloud sections 掛載。使用 P12a reader／projection、P12b audit adapter及既有 typed mutation writer；不得掛 prototype ReportScreen/store 或新增裸寫。
- 只在有效 Google holder 下讀資料。common props 沿用 db／identityKey／leaseEpoch／onNavigationStateChange。所有 request 與 action 綁 scope/query generation；切帳號、租約、range或帳戶後舊回應不得落入新畫面。失權清完整資料與草稿、鎖導航；pending保留命令ID依既有recovery。
- 歷史頁是 server cursor query，不接全歷史／全commands listener，也不寫本機業務cache。使用完整model的範圍、scope、datasetId、sourceSeq與完整性，不從畫面分頁拼湊輸出。

## F2 報表

1. 日期 today／week／month／custom；預設由server lease台北今天推導。本週週一開始，custom最多31日；錯誤range有中文提示，不截短。
2. 日摘要以dayheads既有口徑呈現份數／餐費／收款留存／櫃台收支／退款與淨現金。區間不加總現金存量；每個closed日分別列原實點、補記淨額與有效現金。不能由heads猜orderUnpaid。
3. 完整明細讀取後可原始／合併切換。UI分頁只影響呈現，不能改合計或輸出完整性；顯示載入中／尚未完整，不用假0餘額。
4. 編號／現名／aliases／交易快照名搜尋提供候選帳戶，選一個後scope=該ID；清除回全區間。未選定的多候選搜尋不改輸出scope，按鈕與欄位清楚說明。日摘要／日結仍是全日，與選定帳戶結果分開標示。
5. 原始交易顯示status、當時姓名、餐點快照、操作者、台北時間、由完整有效歷史重算的餘額及回填標記；voided原列可查但不算有效合計。補記是獨立區塊，不冒充餐點或學生收款；帶原因/actor/time、原settlementRevision、計入或不再計入。
6. 日結入口跳既有日結頁，保留選定dayId；搜尋或週月範圍不得縮小關帳口徑。

## F5 查帳與歷史更正

1. 由當前學生編號映射studentId，不另掃studentCodes集合。讀完整帳戶歷史及前綴後才顯示逐筆餘額，標「依目前更正後資料重算」與sourceSeq。
2. 展開交易可看原command／更正command before/after、reason、actor/time；日結版本另列，不把目前重算餘額當作當時現金快照。日／帳戶audit只做對應索引分頁，不掃全commands。
3. 未曾關帳的歷史日（status=open、lastSettlementRevision=0）允許active交易的更正／作廢；使用現成CorrectTransaction／VoidTransaction契約，理由必填、server tx/student/day revisions，輸入採嚴格整數，不改歸屬、日期、建立時間。
4. closed或曾關帳後reopened學生歷史在此介面皆唯讀，提示現金差額到日結補記；不新增重開學生交易入口。這是本UI政策，不宣稱backend Rules已收緊。
5. 提交前固定ID、payload、targets與versions，未知結果查／重試同ID，禁止連按與導航、不得換ID。明確conflict後重讀完整history與heads再讓使用者確認；不得默默用新revision重送舊內容。
6. 僅提供合法的歷史更正／作廢，不把today-only CancelRefund／Undo拿來處理過去日。沒有完整prefix／帳戶head對不上就不允許改帳與輸出。

## CSV 與列印

1. 只對完整固定model啟用動作；scope與模式與畫面明細一致，記sourceSeq。輸出transactions原始/合併、settlements、post-close-entries、audit；無帳戶意義的日結/補記輸出只能all scope，UI有明確範圍說明。
2. 點擊時固定內容、range、scope、mode及commandId→提交P12b稽核→確認receipt→發起download/print；pending/unknown不再產生新ID或重複觸發瀏覽器動作。成功訊息只說「已發起」，不說「已保存／已印出」。
3. Print model包含真實起訖日、scope、模式、sourceSeq及完整rows，不只目前可見頁。使用同頁print surface與print CSS，避免await稽核後才window.open造成popup被阻擋；print surface固定於這次action model，不能被之後非同步query覆蓋。
4. React effects／StrictMode重跑不得對同一已確認command重複發起動作。瀏覽器取消列印仍保留「發起」稽核，不能宣稱知道使用者印了幾張；分頁關閉/重開的持久故障處理屬P13，本批不新增本機帳務儲存。
5. 畫面／CSV／print均使用同projection，不能各寫一套金額/份數/合併/標記算式；保留CSV既有欄位與安全escaping，合法負數餘額不可誤成公式。
