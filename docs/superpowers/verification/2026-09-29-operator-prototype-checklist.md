# 本人可照做的前端 UI 驗證清單

這份是 **團隊修正後的目標驗收**，不是說目前已全部能做。遇到入口不存在，記「未提供」，不要用 DevTools 補資料。一次只驗本批；沒有打勾不代表程式未寫，打勾代表你本人實際操作符合。

日期：2026-09-29；依 [spec](../specs/frontend-prototype-workflow-spec.md)；團隊交付順序見 [plan](../plans/2026-09-29-frontend-prototype-refocus.md)。

## 開始之前

團隊先提供練習啟動指令、網址、版本／commit、可用批次，畫面要明確顯示「本機練習」。不要在一般模式／現有5173按清除。以下清除／還原均限你明確選定的練習資料集，先匯出快照；確認對話框應列出清除範圍。

記錄：日期____　版本____　網址____　瀏覽器____　螢幕____　縮放____　字級____　結果 Pass／Fail／未提供／未測。

用1920×1080 PC及自己的MacBook Pro 13吋各驗一次，先100%普通字，再大字／125%；記實際可用視窗尺寸。團隊另提供1920×950、1440×727、1280×680結果。實體鍵盤測數字列、右側數字鍵盤、中文輸入法。日常每天只有晚餐，應不用先選午／晚餐。找零自己處理，系統只輸入實際留下的金額。

## M4：換成自己的日常資料

- [ ] 建立新的空白練習資料集，手動輸入10–20個熟悉帳戶／期初；包含欠款、已有餘額、教職員、共用帳戶。每筆對照來源並記期初日期，不把期初當今天收到的錢。
- [ ] 模擬3個晚餐日，每天先存快照，再連續登記至少10筆；測補繳、特殊餐、取消與查往日。
- [ ] 至少一次單靠鍵盤做完正常訂餐／收款；記哪一步需要滑鼠、找按鈕、猜Enter會做什麼。
- [ ] 一次刻意記錯，自己從歷史找出、填理由修正，對照預期餘額／現金，再關帳。
- [ ] 清練習交易保留名單再重跑、還原完整快照各一次；確定你可以自己開始，不需工程師在旁。
- [ ] 自己能回答：誰訂幾份、收多少、現在餘額、何時改過／為何、抽屜差多少。全部答得出再簽收。
