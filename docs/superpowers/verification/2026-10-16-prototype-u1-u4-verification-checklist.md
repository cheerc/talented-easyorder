# 本人可照做的前端 Prototype（U1–U4）操作回饋驗收清單

這份文件提供 CheerC 本人在本機練習環境中，針對 2026-10-15 操作回饋（U1–U4 批次）逐項驗證的具體操作步驟與預期結果。

- **適用版本**：整合 PR #488 合入 main 後之版本（merge commit `6ae1909639f56aa6d36524406e700554891f6328`）。
- **環境要求**：本機單機練習模式（port 5174），完全隔離於雲端 Firebase，不影響正式帳務。
- **資料保護原則**：全程使用合成範例學員（「測試甲」、「測試乙」、「測試丙」），不使用真實個資，不需附加真實截圖。
- **邊界說明**：本清單為 **前端 Prototype 互動行為定稿之驗收**；Prototype 驗收通過不代表雲端正式後端全部完成（雲端 P08 訂餐、P09a 繳費、P09b 退款等由後端線接續落實）。

## 驗收前起點準備（唯一從空白開始的精確腳本）

為確保後續各項測試（E 付款明細、F2 報表、U2c 隔日開帳比對、U3 缺號列、U4 退款）具有正確且互不衝突的前置資料，請依下列步驟建立乾淨起點：

### 1. 啟動練習模式
專案根目錄未包含頂層 `package.json`，請使用下列指令之一啟動：
```sh
# 方式一：從專案根目錄帶 --prefix 執行
npm --prefix frontend run dev:prototype

# 方式二：切換至 frontend 目錄後執行
cd frontend && npm run dev:prototype
```
瀏覽器開啟 `http://127.0.0.1:5174`，確認頂部標題列清楚標註「本機練習」。

### 2. 備份並清空練習資料
1. 點擊頂部導航切換至「**F3 今日設定**」。
2. 下滑至「**練習資料**」區塊，若原本瀏覽器有個人練習資料，可先點擊「**匯出快照**」下載保存。
3. 點擊「**從空白開始…**」，在彈出的紅色確認對話框中點擊「**確認清空**」。畫面提示「已改成空白資料。」

### 3. 建立前一日（D-1）開帳與關帳數據（供 U2c 開帳比對）
1. 在「練習資料」區塊的「**練習營業日**」輸入框（`aria-label="設定練習營業日"`），選擇昨日日期（例如 `2026-10-15`，以下稱 D-1 日）。
2. 上滑至「**每日開帳金額**」區塊，在「**開帳金額 (元)**」輸入框輸入 `4000`，點擊旁邊的「**儲存開帳金額**」按鈕儲存確認。
3. 切換至「**F2 報表**」，點擊下方「**日末點現金**」展開關帳表單。
4. 在「**實際點算金額**」輸入框輸入 `4000`（此時應有現金為 4000，差異顯示「✓ 平」）。
5. 點擊「**確認關帳**」，在確認對話框中點擊確認完成關帳。

### 4. 切換至今日（D）並建立專用學員與菜單
1. 回到「**F3 今日設定**」，在「練習營業日」點擊「**下一個練習日**」（或設定為今日日期，如 `2026-10-16`，以下稱 D 日）。
2. 在「**今日餐點設定**」，輸入品項「**排骨餐點**」，單價輸入「**90**」，點擊「**儲存設定**」。
3. 在右側「**學員管理**」卡片上方常駐之「新增帳戶」表單中（表單包含帳戶編號、姓名、期初餘額、期初備註，無別名欄），依序填寫並點擊「**新增帳戶**」按鈕建立 3 位專用合成學員（各自獨立職責，互不干擾）：
   - 學員 1：帳戶編號 `001`、姓名「**測試甲**」、期初餘額 (元) `300`（**專供 U3 驗證缺號、停用與改號**；別名非必填，若欲測試別名可在建檔後於清單點擊「編輯」補上）。
   - 學員 2：帳戶編號 `003`、姓名「**測試乙**」、期初餘額 (元) `300`（**保留使用中狀態，專供 U4 於 F1 驗證退款與 5 秒撤回**）。
   - 學員 3：帳戶編號 `006`、姓名「**測試丙**」、期初餘額 (元) `0`（**專供 U2a 於 F1 訂餐並產生交易明細，結餘變 10，不影響 003**）。

## 六、U4 學生帳戶餘額退款（#1）

| 項目 | 操作步驟 | 預期結果 |
|---|---|---|
| **U4-01** | 切換至「F1 POS櫃台」，搜尋使用中且有餘額之學員 `003`（測試乙，期初餘額 $300），按 **W** 進入繳費模式。 | 繳費金額輸入框右上方出現「**退款**」按鈕；若換成餘額 0 元之帳戶，退款按鈕自動停用（disabled）。 |
| **U4-02** | 點擊「退款」按鈕開啟「退款給學生」對話框。 | 顯示學員姓名「測試乙」、目前餘額「$300」，金額預設為全部餘額（$300），提供快捷理由標籤（「結清離班」、「溢繳退還」、「取消課程」）。 |
| **U4-03** | 對話框開啟時，按鍵盤 Q/W/E/F1–F5/方向鍵/Enter。 | 鍵盤快捷鍵被對話框有效攔截，不穿透至背景觸發換頁或下單。 |
| **U4-04** | 理由留空，或輸入超過目前餘額之金額（輸入 `500`）。 | 確認按鈕保持停用，或提示「退款金額不能超過目前餘額」及「請填寫退款理由」。 |
| **U4-05** | 輸入金額 `100`，點選理由「溢繳退還」，點擊「**確認退款**」。 | 退款成功，學員餘額扣減 $100（變為 $200），畫面上方顯示綠色成功橫幅，並出現「**撤回這筆 (5秒)**」按鈕。 |
| **U4-06** | 在 5 秒倒數內點擊「**撤回這筆**」按鈕。 | 退款交易立即被撤回，學員餘額即刻復原為 $300，稽核軌跡記錄「送出後立即撤回」。 |
| **U4-07** | 再次對 `003` 執行退款 $100（理由「溢繳退還」），送出後放開鍵盤與滑鼠，靜待 5 秒倒數結束。 | 5 秒倒數完畢後，撤回按鈕自動消失，退款正式生效（餘額確定為 $200）。 |
| **U4-08** | 查看「F2 報表」與 E「付款明細」。 | F2 獨立列出「退款」卡片（`totalRefund: $100`），淨現金依公式 `收現 − 支出 − 退款` 正確計算；E 付款明細列出退款項目與金額 `−$100`。 |
| **U4-09** | 切換至「F3 今日設定」之學員管理清單，找到在 U3 步驟中已停用並改號之 `009 測試甲`（餘額 $300），直接點擊其列上的「**退款**」按鈕。 | 停用學員**不需先執行恢復帳戶**即可直接辦理退款；輸入金額 `120` 與理由「離班結清」確認後，餘額變為 $180，且手續完成後仍維持「已停用」狀態。 |
