# 刷臉訂餐平板（talented-faceorder）交接規格

日期：2026-10-13。取代 [ipad-face-auth-handoff-spec](ipad-face-auth-handoff-spec.md) 的 iPad 構想；辨識端改為 Android 平板 App [talented-faceorder](https://github.com/cheerc/talented-faceorder)（其 `docs/PLAN.md` §3 是同步規劃的另一半）。

這一輪**只做 easyorder 的畫面與資料接口，連線用本機模擬，不做後端、不改 faceorder**。後端（Firestore 結構、平板帳號權限）另寫計畫文件。

## 1. 產品決定（CheerC 2026-10-13）

| 項目 | 決定 |
|---|---|
| 分流 | 平板**只訂餐、不繳費**。要繳費的人到櫃台；刷臉的人本來就沒有要付錢。 |
| 入帳 | 平板的訂餐**自動入帳**，不經櫃台確認。這是對「PC 是帳務權威」原則的明確例外，只限下面的規則。 |
| 第二次刷臉 | 平板顯示「加訂一份」與「取消訂餐」兩個按鈕；後台接受同一帳號的第二份（兄弟姊妹共用帳號）。 |
| 不輸入文字 | 刷臉的人不打字。取消的理由由系統填「平板取消訂餐」。 |
| 取消與退費 | 餐費**一律留在帳戶**；要退現金到櫃台。被取消的那筆當場有付現金、或這個人當天在櫃台繳過費時，平板提醒「退餐費請到櫃台。」只用儲值餘額的不提醒。 |
| 共用帳戶 | 沿用現行做法：一個帳戶給多人用時，帳戶名稱寫成「陳小明/陳大強」，櫃台打任一個名字都找得到，不需要別名。easyorder 不用改；只有平板端要能讓兩張不同的臉對應到同一個訂餐編號。事件可選填「成員」（平板知道是哪張臉時），明細備註顯示「刷臉訂餐（成員）」；不送時只寫「刷臉訂餐」。 |
| 註冊同步 | 平板的註冊資料一有異動（新增、停用、重新註冊），主動回報後台；F3 帳戶清單顯示人臉註冊狀態（唯讀）。 |
| 櫃台畫面 | 只多一個「刷臉訂餐」動態（快速看誰是刷臉的）；統計照舊算全部訂單，不另拆刷臉數字；明細備註顯示（刷臉）。頂部只有平板在線／離線。 |

## 2. 事件與規則

平板送出 `FaceOrderRequest`（`frontend/src/domain/faceOrder.ts`）：`eventId`（唯一）、`deviceId`（`faceorder-01`）、`action`（`order`／`cancel`）、`studentId`（＝訂餐編號）、選填 `memberName`、`businessDate`、`recognizedAt`。

後台處理（`store/posActions/faceActions.ts` 的 `handleFaceEvent`）回傳 `FaceOrderEvent`：`status`（`accepted`／`rejected`）、`reason`、`notice`、`transactionId`、`studentName`、`handledAt`。平板依此顯示結果；**不得在後台確認前宣稱訂餐成功**。

| 順序 | 檢查 | 結果 |
|---|---|---|
| 1 | 同一個 `eventId` 已處理過 | 回傳第一次的結果，不重複入帳 |
| 2 | 缺編號、帳戶、日期或平板 | 退回「資料不完整，請到櫃台。」 |
| 3 | 找不到帳戶 | 退回「找不到這個帳戶，請到櫃台。」 |
| 4 | 帳戶停用 | 退回「這個帳戶已停用，請到櫃台。」 |
| 5 | 這一天已關帳 | 退回「今天已關帳，請到櫃台。」 |
| 6a 訂餐 | 這一天沒有晚餐設定 | 退回「今天還不能訂餐，請到櫃台。」 |
| 6a 訂餐 | 其他 | 入帳：訂餐、今日便當、應收＝當天價格、實收 0；來源 `ipad_handoff`（畫面顯示「刷臉平板」），操作人＝平板編號，備註「刷臉訂餐（成員）」 |
| 6b 取消 | 這個人當天沒有訂餐 | 退回「今天沒有訂餐可以取消。」 |
| 6b 取消 | 其他 | 取消當天**最後一筆**訂餐（不論刷臉或櫃台登記）；有收款的改成同金額繳費（錢留在帳戶），沒收款的直接取消；稽核記原單、理由「平板取消訂餐」、平板編號；需要時附「退餐費請到櫃台。」 |

關帳鎖、稽核、餘額重算全部沿用櫃台的同一套程式（M2／M3）。

## 3. 平板讀得到的資料（隱私邊界）

`faceDailyStatus`：帳戶名稱、是否啟用、當天已訂幾份。**不含餘額、交易明細、價格。** 已訂份數 > 0 時，平板顯示「加訂一份」「取消訂餐」。

## 4. 本機模擬

練習模式的 F3「模擬刷臉平板」：選帳戶與成員 → 依當天份數顯示「正確，訂餐。」或「加訂一份／取消訂餐」→ 用平板的文字顯示結果；另可回報註冊異動（狀態與張數）、切換上線／離線。事件與平板狀態存進練習資料與快照；「只清除練習交易」時一起清掉事件。

## 5. 需要 faceorder 配合的地方（不在本 repo，另寫 brief 給 local agent）

- 第二次刷臉（當天已訂）顯示「加訂一份」「取消訂餐」兩個按鈕。
- 取消後依後台回傳的 `notice` 顯示「退餐費請到櫃台。」
- 放寬「一個訂餐編號只能一張臉」：同一編號可註冊兩張以上不同的臉（共用帳戶，例如「陳小明/陳大強」）；事件可選填 `memberName`。
- 註冊異動時主動回報（狀態與張數）。

## 6. 不在這一輪
