# PC 櫃台前端 prototype workflow spec

狀態：2026-09-29 交接提案，待 project team review 與分批實作／operator 驗收。不是現行功能完成聲明。依據見 [audit](../reviews/2026-09-29-frontend-workflow-audit.md)，排程見 [plan](../plans/2026-09-29-frontend-prototype-refocus.md)。

## 1. 適用範圍與優先順序

只定義前端、本機持久化與可測資料模型。不要修改 Firebase schema、rules、同步協定、雲端部署或人臉辨識。既有 React／Zustand／domain／IndexedDB 儘量沿用；可以補必要的 local adapter，不重寫應用框架。

使用者 2026-09-29 指示 > 本 spec 本輪目標 > 未衝突的 living specs > 歷史 plans／V3。本 spec 替代本輪的搜尋焦點、成功回饋、取消清除、空白建檔、更正／作廢、期初與現金顯示要求。舊 spec 中「已完整實作」只代表當時的聲明，不能沿用為 UI 驗收結果。

## 2. 最小產品與畫面責任

operator 已確認每天只有晚餐。不做午晚餐切換。收款欄輸入實際留存金額：餐費90，找零後輸入90；輸入100表示其餘10留在帳戶。找零由操作者處理，不新增交付面額／找零欄或找零計算器。

| 區域 | 主要任務 | 常態顯示／次要內容 |
|---|---|---|
| F1 櫃台 | 找人、訂餐、收款、查當日付款明細、進下一位 | 主操作＋最近帳戶；異常／其他餐點／更正按需要展開 |
| F2 今日帳 | 看今日明細、餐費／收現／付出、查差異、關帳 | 明細優先；點現金／關帳以明確入口展開；週月篩選收於次要區 |
| F3 今日設定 | 當日餐費、供應商、期初現金；名單與練習資料入口 | 每日必要設定優先；主題與模擬工具放次區 |
| F4 供應商 | 名稱、電話、備註、停用 | 保留小型名冊，不加採購／庫存／圖片 catalog |
| F5 歷史 | 帳戶＋日期查交易、看更正、查結帳版本 | 「交易／結帳／更正紀錄」三種查詢；共用既有查詢元件 |

F1 大字身份、目前餘額、餐費、實收、完成後餘額要能一次讀懂。可見的「確認登記 Enter／確認收款 Enter」與「取消 Esc」要與鍵盤走同一 action。不要再新增一整排快捷鍵或多層模式。

## 3. 本機練習資料（S）

### S-ENV 環境

- 新增明確的本機練習啟動方式（建議 `npm run dev:prototype`，屬待實作指令）。即使開發者已有 Firebase env，本模式也不初始化 Auth／Firestore、不啟 subscription／sync queue。
- 使用獨立 origin 及儲存 namespace，不能依賴「沒有 .env」的默契；畫面持續標示「本機練習 · 僅此瀏覽器」，展示模擬營業日。
- local save 成功才說「已儲存到此瀏覽器」。沒有遠端確認時不得顯示已同步／備份完成。讀寫失敗保留輸入並說明可採取的動作，不能靜默回填範例造成資料看似正常。
- 保留原正常啟動路徑。練習專用旗標／日期／資料不滲入一般模式，回歸測試確認隔離。

### S-DATA 起點與重置

提供四個清楚分開的入口：

1. **從空白開始**：0 帳戶、0 供應商、0 交易、0 更正／結帳、無當日菜單；用步驟提示建立帳戶→供應商／餐費→期初現金。
2. **載入驗收範例**：固定匿名 fixture，不隨日期亂數改金額；資料版本可見。
3. **匯出練習快照／還原**：完整 JSON 含 schemaVersion、資料集 ID、匯出時間、所有名單、期初、每日菜單、交易、稽核、結帳／重開版本、模擬日期。CSV 僅查帳輸出，不能當完整還原。
4. **只清除練習交易**：可選保留名單／供應商／期初，明示交易、更正、關帳、日現金工作階段一併清除。預覽數量，不能留孤立更正或舊關帳狀態。

清除或載入範例前先可下載快照，顯示範圍與筆數並要求明確確認；Cancel 不改任何資料。還原先解析驗證／預覽，再原子替換；schema 不支援、重複 ID、缺 parent、金額非法、跨資料集混入等錯誤不得部分寫入。保留上次狀態直到新狀態成功保存；中途故障後重開仍能回到一個完整版本。不得把全站 localStorage.clear 當重置。

### S-ROSTER 名單與期初

- 最少欄位：帳戶編號（字串）、顯示姓名、可選別名、期初餘額、期初日期；零／負餘額均合法整數。保留 `001`，不強制補零或轉 number；同 ID 阻擋，同名顯示警示但允許以不同 ID 區分。
- 允許學生、教職員及共用帳戶；這輪不要求照片、班級、個人資料完整才能訂餐。
- 期初有來源／備註與建立紀錄，獨立於今天現金收入；有交易後改期初需走可追溯更正，不可直接改 currentBalance。
- 可修改姓名／別名、停用／恢復。停用者不出現於正常訂餐搜尋，歷史仍能查；歷史姓名／餐費快照不跟主檔改寫。
- 先完成手動逐筆建檔；批次貼上／Excel 匯入不是本輪前置條件。

### S-DATE 多日模擬

練習營業日由 UI 明確設定；另保留真實建立時間。可「下一個練習日」並保留前日交易／結帳；每日日菜單、現金開帳有自己的 date key。檢視日期不等於當前可寫營業日。切日若有草稿先確認丟棄或返回，不暗中帶到新日。不需修改作業系統時間。

## 4. F1 鍵盤與狀態契約（K）

| 狀態 | 操作／焦點 | Enter | Escape／離開 |
|---|---|---|---|
| idle 搜尋 | F1／完成返回後焦點在搜尋，編號、中文／英文姓名皆直接輸入；Down/Up 只移動可見高亮 | 有結果選高亮，無結果不送單；唯一 exact ID 優先 | 有搜尋字先清空，留搜尋焦點；不得改交易 |
| 已選帳戶／訂餐 Q | 金額欄焦點；身份、當日餐費、帳戶餘額、預覽、當日已訂份數可見 | 一次建立一份；空收款=0；若已有訂餐進明確加訂確認 | 清除人、收款、特殊餐、標籤、錯誤與確認狀態，回搜尋 |
| 繳費 W | 同一帳戶／金額欄；保留輸入金額並即時更新預覽，餐費為 0 | 正整數收款；空／0 不建立交易並顯示原因 | 同上 |
| 付款明細 E | 唯讀列表，顯示今日付款明細與底部合計，提供「查看全部紀錄」跳 F5 交易查詢，Tab 到明細／更正入口 | 只操作目前焦點的控制項，不能隱含送交易 | 離開帳戶清完整草稿 |
| 特殊餐編輯 | 明確的「餐點／原因」「餐費」，Tab 可完成 | 在品項文字框不送整張單；由可見確認控制回預覽 | 先取消特殊餐子流程回當日預设，再取消帳戶；每層意義顯示在按鈕 |
| 重複訂餐確認 | 預設安全取消；顯示已有幾份、這次金額、將加一份 | 要一次新的明確確認，長按不能穿透 | 關閉確認，不增加任何交易 |
| 收支流程 | 保留入口 A（僅非文字輸入焦點），另可從搜尋 Tab 到按鈕 Enter；依次輸入金額／方向／用途 | 只進下一步；最終預覽明確確認 | 子步驟回上一步；最後取消回搜尋 |
| 儲存中 | 禁止再次送出；可見正在儲存 | 忽略重送 | 不讓取消把正在提交當成未提交；完成或失敗後提供下一步 |
| 成功 | 顯示此筆結果與最近交易；移除可再次計算的舊草稿 | 下一位，焦點回搜尋，不重送上一筆 | 關閉完成回饋，回搜尋 |
| 失敗 | 保留同一人／輸入，說明未儲存或狀態待確認 | 已確定未提交才可重試；重試用同一 operation ID | 可取消未提交草稿；不得默默吞單 |
| 已關帳／非目前營業日 | 查詢唯讀，明示原因與返回可操作日 | 不得寫入 | 不提供可繞過日期鎖的快捷鍵 |

共同規則：

- 搜尋使用同一 active／ID／name／alias 規則；不要維護 UI 與 domain 兩套 filter。未找到顯示「沒有符合的帳戶」，高亮項進可見範圍（滾動或分頁），新查詢重設選取 index。exact ID 與 alias 衝突優先 exact；多個 alias 匹配需選人，不自動猜。
- 保留 Q/W/E 使用習慣。在文字欄／中文組字時字母是文字；數字金額欄可用 Q/W/E，但組字中不觸發任何快捷鍵。檢查 isComposing、composition events、repeat；Ctrl/Alt/Meta 組合不得落入無修飾快捷鍵。
- 只高亮一個實際可操作焦點；模式選取與鍵盤焦點外觀可區分。Tab／Shift+Tab 使用合理 DOM 順序，不由全域 Enter 搶走按鈕、文字區、select 的原生操作。
- F1–F5 導航有草稿時提供「保留並返回／捨棄」的明確離開處理；最小實作可用取消離開／捨棄草稿兩選項。Modal 優先於全域快捷鍵，含新增供應商、修改、作廢、特殊餐、關帳／重開；焦點困在 modal，關閉回觸發處。
- 完成後仍以一次 Enter 到下一位作為保留現況的第一版，不卡在倒數。不要增加每筆收款二次確認；只在加訂、更正、作廢、跨日／捨棄草稿等有必要時確認。是否自動跳下一位，等本人測速後再決定。
- 每個功能有滑鼠等價入口，快捷鍵提示只顯示當前有效的鍵；不能靠背鍵才知道如何送出。
- **右上角餐點計數（U2a）**：固定兩行顯示，其他餐點為 0 亦顯示避免跳動。第一行「今日餐點（{菜單名稱}）  N」（無菜單顯示「今日餐點（未設定）」，名稱過長以省略號截斷，hover 顯示全名）；第二行「其他餐點  M」。
- **最近帳戶摘要（U2a）**：依當天有效交易內容顯示「今日餐點 N」「其他餐點 M」「今日餐點 N・其他餐點 M」或「僅繳費」。
- **E「付款明細」與查完整紀錄（U2a）**：E 鍵由「訂餐狀況」更名為「付款明細」，標題顯示「{姓名} 今日付款明細」，列出時間、項目（今日餐點／其他餐點／繳費）、餐費、收款、刷臉標記、編輯與刪除，底部顯示今日餐費、今日收款與帳戶餘額；右上角提供「查看全部紀錄」按鈕，點擊跳至 F5「交易查詢」並精確鎖定該帳戶（exactStudentId），自動設定起訖區間為該帳戶最早營業日（期初與交易最早者）至今天；操作者若手動修改搜尋框文字則解除鎖定回到一般查詢。
- **移除檢視歷史（U2a）**：移除原 F1「檢視歷史」（WeeklyHistoryView），查單一學生完整歷史一律使用 E「付款明細」之「查看全部紀錄」進入 F5。

## 5. 帳戶、餐費與現金契約（L）

以下是產品運算與驗收 oracle，不是正式財會制度；實作沿用既有純函式，但修正已發現的前端資料不一致。

| 名稱 | 定義 |
|---|---|
| 帳戶目前餘額 | 期初餘額 + 有效收款 − 有效餐費 − 有效退款 − 實際退還到帳戶外的款項 + 明確更正差額；有效 refund 減少餘額 `amount`；不得重複計入被替代版本 |
| 一般訂餐變動 | `paidAmount - mealPrice`；未收錢可負餘額；已有餘額不產生實際現金移動 |
| 學生帳戶退款 | 交易 `type: 'refund'`，退款金額以正整數記在 `amount`（`paidAmount` 與 `mealPrice` 固定為 0）。帳戶餘額 −`amount`、櫃台現金 −`amount`；不算餐費與份數。金額必須是正整數且不能超過目前餘額，理由必填，停用帳戶亦可退款 |
| 櫃台應有現金 | 當日期初現金 + 實際收款 + 其他現金收入 − 付供應商等現金支出 − 實際退款 |
| 點算差異 | 實際點算 − 應有現金；差異不是自動產生的收入／支出，也不能再扣一次 |
| 訂餐份數 | 顯示為「今日便當 N 份 ＋ 其他 M 份」（2026-10-13 本人決定）：向供應商叫便當只看今日便當 N；「訂購其他餐點」M 份另列清單（帳戶、品項、價錢）。訂購其他餐點的品項記在交易上，之後改備註或當天改價都不改變分類。有效訂餐總數＝N＋M（結帳紀錄的 orderCount）。金額 110 不代表兩份 |
| 交易筆數 | 有效訂餐、繳費、櫃台收支、退款的筆數（未收款訂餐也算一筆）；作廢／更正歷程另列，不能重複加總 |
| 目前欠款 | `max(0, -目前餘額)`；「當筆未收餐費」不等於這個數字 |

總餐費不是付供應商的現金支出；不能扣學生餐費時再扣現金。Excel 的「餘額」有時是當列淨額，系統文案要分開「本次變動」「交易後餘額」「目前餘額」。歷史範圍中顯示截止餘額需明確標註日期，不能標成目前餘額。

金額為整數 TWD；期初可正可負，餐費／一般收款／退款金額不得負數。正常訂餐可收 0；繳費與退款必須 >0（收款不可為負數，退錢給學生請用「退款」）。使用者輸入非法或超範圍值要可讀錯誤，不靜默四捨五入、截成另一數字或改回預設。最大值沿用經確認的 domain 限制，邊界列入測試。

### L-TRACE 最小追溯記錄

每筆保留穩定 ID、帳戶 ID／姓名快照、營業日、建立時間、餐點／供應商快照、餐費、實收、變動、交易後餘額、來源、操作人標籤、本機保存狀態。單機標籤可以是「本機操作員」，不能冒充已驗證登入者。

所有更正／取消／作廢／撤回都保留：原紀錄、前後值、原因、操作時間／人、原交易 ID、revision／關聯 ID。正常 UI 不提供硬刪除已保存交易。最小方案可維持現行有效交易 projection + 不覆寫的完整 audit revisions，無須建整套 event-sourcing 系統；兩者必須同一持久化單位保存。空理由阻擋，預設 `edit`／`delete` 不算業務理由。

- 作廢錯誤紀錄與實際退現分開。作廢一筆「其實沒收到」的誤收款不應再建立一次退款支出。
- 取消已收款訂餐先選「只取消餐費、款項留帳戶」或「取消餐費並實際退還本筆收款」，明示退款額、餘額和現金各自變化；其他歷史款項不能一起退。預設不能自動退現。
- 學生帳戶餘額退款（`type === 'refund'`）記錄於獨立交易，支援 5 秒撤回、更正與刪除；F2 報表單獨列出「退款」一行（`totalRefund`），不與收現（`totalIncome`）抵銷，淨現金算式為 `netCash = totalIncome - totalExpense - totalRefund`。
- 更正重算同帳戶後續交易餘額、目前餘額及全日報表；依營業日／時間／穩定 ID 排序。同時間不靠陣列 index 決定順序。期初來源不得遺失。
- F1、最近帳戶、F2、F5、匯出與重整後一致；分頁／最近 200 筆只是顯示限制，不得限制總計／重算／當日已訂數。
- 原始金額與原因可透過畫面回查；不用理解 `paidAmount` 或複製 UUID 才能追到人。
- 日期時間顯示統一 Asia/Taipei（UTC+8），儲存可採 ISO instant。不要切 ISO 字串冒充本地時間。

## 6. 每日設定與關帳（D）

- 每日菜單依營業日保存，名稱非空、價格正整數、供應商有效；儲存後有成功回饋。已有訂單時改價須告知只影響之後新單，原單快照不改。
- 供應商停用後不供新選擇，歷史名稱／電話聯絡需求可按現有資料能力呈現；不得硬刪有引用對象。不擴展採購流程。
- F2 預設今日明細；點帳戶可展開原始交易，更正入口綁原交易 ID。櫃台收支獨立區塊，原單與更正可互相到達。
- 關帳顯示同一天的期初、實收、實付、應有現金、實點與差異。有差異必填原因；不能用姓名搜尋／報表週月範圍縮小關帳總額。0 差異不強迫填無意義備註。
- 本機練習的關帳不依賴 Firebase 排隊狀態；保存成功才鎖日。一般模式同步政策不在此更改。
- 關帳日所有新增／更正／作廢入口與 store action 都擋寫。重開有理由、舊結算版本可見；更正後再關產生新版，不覆寫舊點算紀錄。F1 仍只對目前營業日收單。
- 次日期初現金可帶入前一個營業日（非僅昨日，如遇週末取最近一個已關帳日）最後一版關帳點算作建議（若同日重開則優先取上次開帳金額），但必須讓本人確認與輸入實際取出／補入；不把 4000 或前日金額當永遠正確。
  - 開帳金額輸入上限為 0–20,000 元（`validateOpeningCash` 阻擋負數、小數或大於 20,000 元，並在畫面提示錯誤，不打開確認框）。
  - 按下「儲存開帳金額」時，依輸入值與比對基準分三種情況顯示確認框：
    1. **和前一天關帳點算不同**：醒目警示與前一個已關帳日（顯示日期 MM/DD）點算的差額（正差 `+$X`、負差 `−$X`），重開日則比對該日上次開帳金額。
    2. **和前一天關帳點算相同**：提示金額與前一個營業日相同，必須強制包含「我已實際清點」勾選框，未勾選前確認按鈕禁用。
    3. **沒有前一天關帳資料**：提示確實清點抽屜現金後確認。
  - 修改已設定之開帳金額時，保留「修改開帳金額會影響今日所有帳務計算」警示，並套用上述三種比對機制。
- F5 可從帳戶／日期查明細、差額、更正／重開；CSV 輸出保留可連回交易的 ID、date、中文可辨欄位說明。既有 CSV 欄位相容性要先比對，不為美化任意破壞。

## 7. 畫面與驗收門檻

支援主要1920×1080 PC螢幕，以及 operator 的 MacBook Pro 13吋。以CSS viewport而非面板原生像素判斷，不能假定13吋就固定某個解析度；團隊需記錄本人的縮放／瀏覽器可用尺寸。

版面驗收基線：1920×950、1440×727（本輪觀察到的桌面視窗）、1280×680；另驗100%／125%瀏覽器縮放與普通／大字。1280基線為保守開發驗證尺寸，不宣稱是本人Mac實際設定。125%時CSS可用空間更小，需保持操作可達，不能以不支援為由要求縮回100%。

- 充足寬度保留主操作＋最近帳戶左右欄；不足時縮窄或收合最近帳戶，保留清楚的展開入口，不移除紀錄。
- 收款與明細可由雙欄重排為單欄；姓名、餘額、金額與確認／取消優先。必要時內容可垂直捲動，焦點自動可見，主操作列可固定但不能遮住欄位。
- 1920×950正常訂餐主流程不需捲動；小視窗允許合理垂直捲動，禁止整頁水平捲動、按鈕被裁切、為塞內容縮成難讀小字。長表格可在其容器內捲動並保留身份欄。
- 以CSS grid/flex、minmax、斷點與有上下限的間距／字級調整，不以整頁transform/zoom縮放。斷點由內容容納決定，建議先驗1200附近與1440附近，不將這些值當固定產品要求。
- Modal限制在可用視窗，內容可捲、按鈕可達、Tab焦點可見；小螢幕也能只用鍵盤走完。非手機／iPad開發，不為行動版再擴scope。
- PWA安裝提醒不遮操作區，練習模式不主動打斷登記。保留theme token，不加新design system。

不以顏色作唯一狀態；欠款、加訂、保存中、已關帳均有文字。按鍵提示清楚、文字欄 label 可關聯。保留現有 theme token，不加新 design system。

固定數字驗證見 [本人清單](../verification/2026-09-29-operator-prototype-checklist.md)。正常一筆編號訂餐目標仍為「輸入 ID → Enter →（收款）→ Enter → Enter 下一位」，不加不必要步驟；先記錄實際速度及錯誤，不把任意秒數當目前已達成的效能。

## 8. 外觀偏好與顯示設定

本機練習模式與雲端模式共用同一套外觀偏好，由單一 UI tweaks store 管理並持久化至瀏覽器本機儲存（不分模式 namespace），解決多元件個別維護狀態與重新整理後遺失的問題。

### 8.1 儲存契約與欄位
- **儲存位置與鍵名**：使用本機 `localStorage`，固定使用鍵名 `easyorder-ui-tweaks`（跨模式共用，不分 prototype/cloud namespace）。
- **資料格式**：JSON 物件，包含三個外觀偏好選項：
  - `theme`：`'warm' | 'light' | 'dark'`（預設 `'warm'`）
  - `scale`：`'normal' | 'large'`（預設 `'large'`）
  - `disableHoverSelection`：`boolean`（預設 `false`）
- **預設值**：`{ theme: 'warm', scale: 'large', disableHoverSelection: false }`。
- **容錯與防護**：
  - 讀取時遭遇遺失、非法 JSON、非預期型別或缺漏欄位時，安全 fallback 至預設值。
  - 所有 `localStorage` 讀取與寫入一律包覆於 `try/catch`，避免無痕瀏覽模式、安全性限制或儲存空間配額耗盡（QuotaExceededError）中斷畫面渲染。
- **生命週期與隔離**：
  - 本偏好僅保存操作介面外觀設定，不含任何學生個資、帳務或認證憑證。
  - 操作者登出、換日、重置練習資料（`resetData`）或執行清除機密資料（`clearSensitiveData`）時，**不得清除**此鍵。

### 8.2 DOM 屬性與樣式同步
- store 狀態更新時同步寫入 `document.body` 屬性：
  - `data-theme`：`'warm' | 'light' | 'dark'`
  - `data-scale`：`'large' | 'normal'`
  - `data-fs`：`'lg' | 'md'`（相容既有字級 CSS 選擇器，`large` 對映 `lg`、`normal` 對映 `md`）
- 在 F3（今日設定）修改顯示設定後，切換分頁導致 F3 卸載與重建時，偏好狀態保持不變，`document.body` 屬性不會被重設回預設值。

### 8.3 跨元件連動
- `hooks/useTweaks.ts` 作為統一存取門面，底層訂閱單一 Zustand store。
- 在 F3 修改「停用滑鼠 hover 選取」後，F1（`PosColumn.tsx` / `SearchBox.tsx`）即時連動套用，在不需重新整理頁面下立即改變建議清單 hover 選取行為。
