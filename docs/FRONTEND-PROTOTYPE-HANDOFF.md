## 這次要做的產品

把「紙本訂飯登記 + Excel 總表／餘額查詢」變成一個 PC 櫃台工具：找人、登記餐費與收款、查餘額、改錯、核現金。主要環境是 20 吋以上、1920×1080 PC 螢幕，也必須適應 MacBook Pro 13 吋的實際可用視窗，鍵盤為主、滑鼠為輔。保留目前 F1 已獲 operator 約七成認可的結構與視覺，不做整站重設計。

「介面簡單」不代表刪除交易明細。平時只呈現下一個動作，查帳時仍能看見原交易、更正前後值、原因、時間及關聯紀錄。現有程式和已 merge PR 是實作基線，不能當成使用驗收通過的證據。

## 已找到的優先問題

1. 搜尋只畫出 6 筆，方向鍵卻能選到不可見的第 7 筆。
2. 取消一位的特殊餐 110 元草稿後，下一位仍帶入 110 元及品項。
3. 收款 100 改為 120 後，帳戶卡餘額 30，最近帳戶與 F2 仍為 10。
4. 無 Firebase 的本機模式仍顯示「雲端已同步／推送中」。
5. 無法從空白手動建立名單與期初餘額；Reset 回到範例，不是空白。
6. 更正介面暴露 `mealPrice`／`paidAmount`，未要求實際更正理由；F5 用技術 ID 查帳。

前三項已透過 UI 重現；第 5 項以畫面及原始碼確認。完整證據與其餘項目見 audit，勿把推測混成已重現缺陷。

螢幕適配採響應式欄寬、間距與重排；不要用整頁 transform/zoom 等比例縮小。小螢幕優先保住姓名／餘額／金額／主動作，最近帳戶可收合。

## 下一步

按 M0 → M1 → M2 → M3 → M4 交付，每批都提供可操作版本：

- **M0：可重複的本機練習環境。** 空白／範例、手動建檔、期初餘額、匯出／還原、模擬日期、明確本機標記。
- **M1：F1 不中斷且不選錯。** 搜尋可見性、特殊餐取消清除、鍵盤與 IME、防連送、可見送出／取消。
- **M2：改錯仍能信任帳。** 餘額一致、保留原紀錄、理由、作廢／退款語義、可讀明細。這批是帳務正確性 gate，不可為了先美化 F2 而延後。
- **M3：一天工作完整閉環。** F3 設定、F4 聯絡資料、F2 查帳／點現金／關帳、F5 回查與重開。
- **M4：本人用自己的資料模擬。** 空白建檔、連續多天、還原重跑、記錄操作阻力，才決定下一階段。

團隊每批附「起點資料、三分鐘 demo、對應測試 ID、已知限制」。operator 不必一次驗全部；M0 通過才放自己的資料，M1 通過才開始長時間 F1 操作，M2 通過才信任更正與餘額。

## 範圍收斂

保留：訂餐、繳費／預存、特殊餐費、查帳、取消／更正、實際櫃台收支、點現金、基本名單／供應商。沿用 Q/W/E 與 F1–F5，不隨意換鍵位。

暫緩：iPad／人臉辨識、掃碼擴充、後端／Firebase 改造、雲端備份、權限系統擴充、菜單圖片／完整 catalog、多商品購物車、進階統計。F6 概覽與主題微調不列本輪驗收 gate。既有功能先保留在次要位置，不先大刪程式。
